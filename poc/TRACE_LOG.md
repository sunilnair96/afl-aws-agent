- **Conclusion: a gateway Lambda target cannot tell who called it.** Anything identity-like in `event` is whatever the caller (ultimately the model) supplied. Trusted identity has to be injected by something that has seen the validated token (the interceptor, P3b) or the Lambda must not rely on it.
- **P3b research (AWS docs, read 2026-10-08): gateway interceptors.** One REQUEST interceptor max per gateway, Lambda only. Input `event.mcp.gatewayRequest` = {path, httpMethod, headers (ONLY if `passRequestHeaders: true`), body (parsed JSON-RPC)}. ## 2026-10-09 — P3b-Cedar: bind `user_id` to the caller's `sub` in policy

- New policy `WhoamiBoundToCaller` (`lambda/whoami/policy_whoami_bound.cedar`): same group check **plus** `principal.hasTag("sub") && context.input has user_id && principal.getTag("sub") == context.input.user_id`.
- **Stage 1 (old broad permit `WhoamiForGroupMembers` still deployed)** - predicted all ALLOW (permits are additive): **correct, 0 prediction errors**, 6 intent gaps. Concrete vulnerability observed: with distinct users, A sent `user_id` = B's real sub and the Lambda received it (and vice versa). (A first attempt was invalid because `TOKEN_B` was actually A's token - the login page reused A's session; the script now refuses identical subs.)
- **Stage 2 (old permit removed, redeployed)** - results: for both A and B: no `user_id` DENY; **own sub ALLOW** (Lambda received the true id); other user's sub DENY; made-up id DENY. 0 intent gaps. (The run was labelled "PREDICTION WRONG" only because it was invoked with stage `old-permit-active`; results equal the `bound-only` prediction.)
- **Conclusions:** (1) `sub` is readable as a principal tag; (2) policy can force a tool argument to equal the authenticated caller, so a Lambda can trust `user_id`; (3) permits are additive - a stricter permit beside a looser one does nothing until the looser one is removed; (4) the gateway never invoked the Lambda for denied calls (not separately checked in CloudWatch for this test).
- Still needed for a real agent: the **agent code** (not the model) must fill `user_id` from the token; otherwise honest calls without `user_id` are denied.
